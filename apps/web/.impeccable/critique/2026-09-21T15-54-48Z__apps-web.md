## New Design Direction for Coffee Ride

Core idea: "the ride is the interface" — concentrate expressiveness into 2-3 specific surfaces (cover photo, route map, hero metrics) while keeping forms/tables/nav exactly as calm as today.

- From refs 1-2 (an AI-agent-ops dashboard "OrchestrateIQ"): borrow ONLY the layout/craft quality — fixed left sidebar with simple outline icons, neat metric cards, clean small charts, strong typographic hierarchy. Do NOT borrow AI-ops terminology/content — must not read as an AI monitoring panel.
- From ref 3 (running app "Step by Step"): borrow real route/photo visual weight and large sport metrics with expressive type.
- From ref 4 (sports landing "Track Your Progress"): borrow restrained, purposeful glass/translucency — never decorative-first, never on dense data surfaces.
- From ref 5 (logo "spectrum.life"): borrow only the structural two-part lowercase domain-lockup idea (different weight per segment) — not the typeface, glyph, or color.

Palette: extend design.md §3, don't replace. Add `--scrim` (semi-transparent overlay, guarantees AA contrast for text over photos) and `--glass-surface` (translucent + blur, always composed under `--scrim`, never used bare for text).

Typography: keep Golos Text (proven Cyrillic support, Russian-first commitment) — get expressiveness from scale/weight already in the approved scale, not a new font.

Icons: adopt lucide-react (already installed, unused) — outline only, 1.5px stroke, 16/20/24px sizes. Never icon-only without a text label.

Cards: one new "photo card" variant for RideCard/ride-detail hero — full-bleed cover photo, scrim gradient, title+metrics overlaid. Every other card stays the current flat hairline-border Card.

Charts: keep ElevationProfileChart's mechanism (single muted fill, floor-not-zero), add a subtle top-edge highlight stroke in the same primary color — no new color, no gridlines.

Map/route: within the existing maps-core/maps-2gis adapter boundary — thicker polyline + a wider lower-opacity "glow" pass underneath (additive MapPolylineInput parameter, ADR-020 precedent). Move the legend into a glass overlay chip on the map's bottom edge. Do NOT put the map on a photo background or add 3D/tilt — crosses into fitness-app territory the brief warns against, and constrains 2GIS attribution terms.

Glass usage rules: allowed only on the map legend, a floating metric chip over the ride-detail cover photo, and a mobile registration bottom-sheet background (button itself stays opaque). Forbidden on any dense data surface (participant table, MetricRow, forms, organizer dashboard grid, StatusBadge) — per design.md §1's "no gradients/glow on data surfaces" rule. Every glass surface with text must sit on `--scrim`, verified against a placeholder-photo test set (no real ride photography exists yet per product.md).

## Logo/Wordmark Recommendation for "coffee.ride"

Not copying spectrum.life's glyph/type/color — only its structural two-part-lockup logic.

Direction: "coffee" in a regular/medium weight, ".ride" in a lighter weight or in `primary` color (same family, not a second typeface); if a mark is wanted, an original route/switchback line motif, not an abstract wave.

Typeface directions: (1) Golos Text at two weights — safest MVP default, zero new risk, literally satisfies design.md §15's "text wordmark in base typeface" placeholder; (2) PT Sans/PT Sans Caption (same foundry as Golos Text, guaranteed Cyrillic quality, more geometric character); (3) Manrope — open-source grotesque with solid Cyrillic, more premium/technological character, wordmark-only (never UI body text). Recommend starting with option 1; revisit option 3 only with a dedicated brand-identity pass.
