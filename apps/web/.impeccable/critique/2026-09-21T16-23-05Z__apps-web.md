Highest-stakes single interaction in the participant journey, on a product whose own operating context is outdoors/cold hands/gloves/pre-dawn — a mis-tap silently removes someone from a ride with zero recovery. [P1] Organizer dashboard has no glanceable status — ORGANIZER_WIDGETS contains exactly one widget (OrganizerProfileWidget: name/description/edit-link only). ## New Design Direction — "Quiet Instrument"

Same core idea as the first run's "the ride is the interface," refined: the calm/warm baseline stays the system of record; the five references contribute craft, not content.

Palette: extend, don't replace. Add `--scrim` (low-alpha warm-near-black wash, applied by the app itself under cover-photo text, never left to an arbitrary uploaded photo's own contrast), `--glass-bg`/`--glass-border` (bg-raised/border at ~72%/60% opacity) for exactly two surfaces. `--chart-secondary` (already exists) stays the hard stop for a second chart hue — never a third.

Typography: keep Golos Text (design.md §4 explicitly forbids a decorative face and 700+ weight). Get expressiveness by pushing the existing top of the scale (36px/600) harder for a small set of "headline metric" moments, not a new typeface.

Icons: adopt lucide-react (already a dependency), one stroke weight (~1.5-1.75px), 20px default, always paired with a text label, text-secondary at rest / primary when active. Domain glyphs only (route, clock, participants, bicycle, coffee cup) — never AI/ops iconography.

Cards: Card.tsx's hairline-border/no-shadow default stays for all dense data. The new glass surface is reserved for exactly two places — the title/status panel over a ride's cover photo, and a new sticky mobile registration bar — both are honestly "floating over other content," never applied to a MetricTile or form.

Charts: keep ElevationProfileChart's exact contract (single muted primary fill, tabular-nums, real-number hover) — it already matches the brief. Extend the same contract to two new organizer-dashboard chart types: a registrations-over-time sparkline and a capacity arc/gauge, primary teal-green only.

Map/route: packages/maps-core's MapPolylineInput already supports per-call color; extend additively with an optional width/opacity parameter (same precedent as ADR-020's marker color/label addition) so packages/maps-2gis can render a route line with more visual weight — still resolved entirely inside the adapter, primary-only, no neon glow.

Glass + AA rules: any glass panel sits over a scrim the app itself guarantees (never the raw uploaded photo), so AA contrast holds regardless of what a user uploads. backdrop-filter degrades to a solid glass-bg fill where unsupported or where prefers-reduced-transparency/prefers-reduced-motion is set.

## Logo/Wordmark Recommendation for "coffee.ride"

A (recommended for MVP): Golos Text, all lowercase, "coffee" at weight 500 + ".ride" at weight 400 in primary color. Zero new dependency or licensing question, Cyrillic already verified since it's the app's own body face.

B: pair Golos Text ("coffee") with IBM Plex Mono (".ride") — Plex Mono is already loaded and Cyrillic-verified for hex/ID display in this codebase, giving a genuine two-register mix without adopting a new face.

C (later, optional): a minimal single-color glyph built from the app's own typed-marker vocabulary already in route-point-colors.ts (a dot + a short curved stroke, echoing a route curl or steam wisp) preceding the wordmark.

Recommend shipping A now, prototyping B if a more distinct lockup is wanted later, C only on explicit request for a mark.
